# Mentavio Session Notes

This directory stores concise daily summaries of product decisions, completed work, discovered defects, approved requirements, and open tasks.

## Purpose

The notes preserve context between working sessions and provide Codex with a clear starting point without requiring anyone to reconstruct decisions from chat history.

## File naming

Use one file per working date:

`YYYY-MM-DD.md`

Example:

`2026-08-02.md`

## Required sections

Each daily note should contain:

1. Session status
2. Completed work
3. Verified behavior
4. Defects discovered
5. Decisions made
6. New or updated specifications
7. Open questions
8. Next actions for Codex
9. Links or references that may expire
10. End-of-session handoff

## Update rule

At the end of each working session:

- summarize only confirmed decisions and observed behavior;
- separate completed work from planned work;
- identify temporary URLs;
- reference permanent SPEC documents;
- record blockers honestly;
- do not leave approved technical requirements only in chat history.
